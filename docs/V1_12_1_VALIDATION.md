# Comic Manage 1.12.1 验证记录

日期：2026-11-18，Windows 11 x64。

## 修复内容

- 修正曾移出列表的旧版本目录重新导入时，因仍被判为“已移出”而跳过父作品名称识别的问题。导入预览与确认使用同一候选逻辑，未勾选的版本不恢复。
- 首次加载资料库时，对可见、本地、未审核、没有成品和人工标题修改保护的旧版本目录进行一次有时间上限的只读来源检查。来源指纹及页数未变时，先备份再整批复核资料版本并回填。任何资料版本、可见性或来源变化均不会造成部分写入。
- 保留已有作者、其他人工资料、明确清空值、自己的 XML、历史审核与成品保护。回填只更新选定元数据及审计，不修改源图片、文件指纹、页数、状态、输出路径或 Komga。
- 作品资料栏从后台读取并始终显示当前元数据规则 v1.3。旧 v1.2 固定提示在显示时标记为历史记录，资料库中的原始迁移证据保持。

## 已验证

- 340 项 Python 核心、导入、元数据、Komga 及回归检查通过，其中新增 19 项覆盖恢复、启动回填、备份、保留字段、整批并发校验、取消与离线来源。
- 44 项 Node 通信、配置和作品组逻辑测试通过；Vue 类型检查及生产构建通过。
- 完整 Electron 桌面流程通过：导入、单独选择版本、分组折叠、编辑、批量审核、模拟 Komga 同步、原图保留及成品验证。
- 使用真实旧格式 JSON 建立四条隔离合成记录，依次经过 v1.2、v1.3 迁移及旧移出/恢复历史。源码服务和打包的原生后台均验证：仅两条版本名称修正、作者保留、其他两条逐字段不变、备份包含修复前资料、刷新/重启不重复修复、只恢复选中版本、源图哈希不变。
- 真实渲染器离屏验收确认：四条记录显示为三部作品，版本组默认折叠；展开后两个版本都显示父作品名，各自保留文字版本；未选中、基本资料及 XML 页签均显示规范 v1.3；旧警告标记为历史。使用新绘制的截图核对布局。
- 在用户资料库的只读备份副本上验证实际两条旧记录：来源指纹和页数相同，两条均获得父作品名、同一作品组及各自文字版本；已填写作者、普通记录及已移出记录保持。仅只读访问 NAS 的目录信息和 XML，没有写入现用资料库、源文件或 Komga。
- 启动来源检查最多等待 5 秒；挂起的只读线程即使后来返回，也不能编辑资料库。备份发生文件系统或 SQLite 错误时，原资料可继续加载。

## 验证范围

本次没有对用户实际 Komga 进行写入验收。后台同步仍由原有已审核元数据和身份校验流程管理；不会因启动名称修复自动提交远端变更。不同操作系统及长期不稳定 SMB 环境尚需实际使用验证。
